# 内容侧前端浏览器走查（2026-10-15）

## 结论

内容侧前端已在**真实浏览器 + 真实 API + 真实 MySQL/Redis** 上走查通过：主题列表、主题详情、发帖/提问、Markdown 渲染与预览、图片上传、回答、评论与两层回复、解决状态、编辑、删除确认，以及匿名身份与越权的界面表现都按预期工作。

走查中发现了 **3 个真实缺陷**（1 个功能性、2 个体验性），均已修复并复测；另有 1 次"疑似中文乱码"经比对字节后确认是**走查夹具自身的编码问题**，不是产品缺陷。

本节所有结论都来自本次实际点击与截图，不使用 mock 或假数据。

## 环境

- 独立 schema `opentalk_browser`（不触碰开发库 `opentalk`）：`cmd/migrate -action up` 建表，`cmd/admin -action seed-boards` 预置板块。
- 两个账号由 `cmd/admin -action create-admin` 创建（注册需要真实邮件验证码，走查不应发信）。角色是 admin 不影响内容规则：权限端点对管理员不给捷径，这一点在走查中被验证。
- API `127.0.0.1:18080`，前端 Vite dev `127.0.0.1:15173`（同源 + 代理），`APP_ORIGIN` 与之一致，`TRUST_PROXY=false`。
- 标签由夹具直接写入数据库；`cmd/admin` 没有建标签的动作，管理端的标签接口在合同里仍是 planned。

## 发现并修复的缺陷

### F1（功能性）任何 401 都会把访客踢到登录页

`api/client.ts` 的 `notifyUnauthenticated` 在**所有** 401 上触发全局"会话失效"处理并跳转登录页。游客打开公开页面时，App 自身的 `GET /api/v1/me` 必然返回 401，于是主题列表、主题详情、板块页全部把访客弹到登录页——与"游客可浏览"直接冲突。同一个原因还让**密码错误**的登录提示被替换成"请先登录后再继续操作。"。

修复：把判断放回唯一的出口——只有"本页相信自己有会话"时 401 才算会话丢失。内存里的 CSRF 令牌正是这个信念（登录成功才设置、退出即清除），因此以它作闸门，上传路径也自动继承同一规则。修复后游客可正常浏览，错误密码显示真实错误。

### F2（体验）上传的图片与上一行文字挤在同一个段落

编辑器插入图片时，只要光标前是单个换行就认为"已经另起一段"，但 Markdown 里连续两行属于**同一段落**。图片与文字共享行盒，图片比文字高且按基线对齐，文字就被压在图片下沿——截图里"站内链接"看起来被图片盖住就是这个原因。

修复：插入时保证两侧各有一个空行，除非边界本身已是空行或文档边缘。同一位置还把"正在回复 #4"改为"正在回复 作者名"，不再把内部 id 暴露在界面上。

### F3（体验）"不能评论"的原因被说成"未登录"

问题已解决或被锁定时，评论框位置显示的是"当前账号无法在此处发表评论。登录后可以参与讨论。"，而回答区同一状态下显示的是"主题已锁定或问题已解决，暂时不能新增回答。"。同一个状态两种说法，且评论那句在已登录时明显误导。

修复：评论框按"已关闭 / 未登录 / 账号受限"三种原因分别给文案，由调用方传入 `closed` 与 `signedIn`。

### 非缺陷：一次夹具编码乌龙

第一次写入的标签在界面上显示为乱码。比对 `HEX(name)` 与 API 响应字节后确认：真正的原因是 **PowerShell 5.1 把脚本里的中文按 ANSI 传给 mysql 客户端**，写进库的就已经是坏字节；应用侧没问题。改用字节精确的 UTF-8 `.sql` 文件重新写入后，`HEX(name)`=E585ACE5918A（公告）、API 返回同样的 UTF-8 字节、界面正常显示，标签选择也可用。记录在此以免被误判为产品缺陷。

同一次走查中还有一次"看起来仍是乱码"，实为同一个页面 URL 未真正重新加载留下的旧 DOM；强制重新加载后消失。

## 顺带修正的脚本

`scripts/smoke-local.ps1` 把 `GET /api/v1/topics` 当作"未实现路由必须 404"的探针，而该端点本轮已实现，脚本会因此失败。探针改为仍然 planned 的 `GET /api/v1/search`。复测通过：健康 200、前端 200、代理 200、就绪 200、未实现路由 404、未知图片 404。

## 未覆盖 / 仍是缺口

1. **回答与评论级没有编辑/删除入口**：详情页只给了主题级入口。权限按 `content_id` 逐条获取，为每条渲染按钮会带来 N 次请求，尚未设计。接口本身支持。
2. **评论只加载顶层第一页**：没有"加载更多评论"，也没有展开某个串根时按 `parent_comment_id` 拉取其全部回复（接口已支持该参数）。
3. **标签 chip 不可点击**：`#/tag/{id}` 路由存在，但列表里的标签没有做成链接。
4. **评论不能配图**：接口接受 `attachment_ids`，界面只给主题与回答接了上传器。
5. **列表不显示回答/评论数量**：合同没有计数字段，需要先扩合同。
6. **删除确认用 `window.confirm`**，不是自定义对话框。
7. 本轮未做并发、负载、无障碍与移动端走查；未测超大图片的内存与耗时。
