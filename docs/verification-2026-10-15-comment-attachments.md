# 评论配图与附件去重（2026-10-15）

## 结论

评论与回复现在可以配图：图片先上传，随评论一起提交（`attachment_ids`），服务端在同一事务里建立关联并把待用附件转为已关联内容。同时修掉了**同一张图片被显示两次**的问题——此前主题、回答与评论都是"正文里一张 + 下方附件条里一张"。

## 实现

- 评论框上方接入与主题/回答相同的 `ImageUploader`：上传成功后把 `![名称](/media/…)` 插入正文，**并且**把附件 id 一起提交。两者都做是有意的——正文插入让图片出现在文字流里，附件关联让图片在作者事后删掉那段 Markdown 时依然属于这条评论。
- 插入正文沿用主题编辑器同一条规则：图片前后各留一个空行，否则 Markdown 会把图片和上一行算作同一段，文字会被压在图片下沿（这正是之前修过的那个缺陷）。
- 提交成功后清空正文与已上传列表。

### 附件去重

公开载荷里没有存储键，只有渲染时要加载的地址 `url`，所以判据是"正文里是否出现过这个 url"（`web/src/lib/attachments.ts`）。这正是 `<img>` 会用到的同一个字符串，因此判成"已显示"的一定就是画面上那张；而用别的方式引用、或压根没引用的图片仍然会在附件条里出现一次。主题、回答（`AttachmentGallery` 传入 `bodyMd`）与评论（`CommentBody`）共用这一条规则。
