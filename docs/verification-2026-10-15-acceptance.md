# 端到端验收（2026-10-15）

## 结论

端到端验收已脚本化并**跑通**：`scripts/run-acceptance.ps1` 建一个全新数据库、迁移、建两个账号、启动 API，然后由 `scripts/acceptance.py` 走一遍真实部署必须survive的路径。**37/37 检查通过，退出码 0。**

脚本进仓库（不是一次性夹具），因为验收是第 9 项的交付物，别人应当能复现：`powershell -File scripts/run-acceptance.ps1`（用 `-Keep` 保留临时库以便查看）。

## 覆盖了什么

| 分组 | 检查 |
| --- | --- |
| 登录 | 两个账号各自登录并拿到 CSRF 令牌（每个账号独立 cookie jar，不会误共享会话） |
| 发布 | 讨论帖、提问（问答板）、匿名帖 |
| 互动 | 回答、评论 |
| 公开读取 | 游客读列表、读单条内容、**搜索能找到刚发布的内容** |
| 私有/公开列表 | 本人内容包含自己的帖子与**匿名帖（并以匿名模式渲染）**；公开主页不列出该账号的匿名帖、且响应不含邮箱 |
| 举报闭环 | 成员举报 → 进入管理队列 → 管理员结案 → **举报者看到结案说明** |
| 审核 | 隐藏后公开读取 404 → 恢复后 200 → 锁定主题 → 禁言 → **被禁言后不能新增发言** → 撤销处罚 |
| 站点结构 | 新建板块、更新板块、新建标签、**同名标签 409** |
| 揭示类 | 管理员删除他人内容 → **读取删除原文（正文一致）** → 缺原因 422 → **匿名追溯指向真实作者并给出审计 ID** |
| 通知与审计 | 回答产生站内通知 → 标记已读；审计里能同时找到本轮 12 种管理动作 |

这同时补上了 B6c 里没走到的三项中可在接口层验证的两项（删除原文读取、板块与主题处置），第三项（搜索页改用共用卡片后的界面复查）仍属界面走查。

## 一处我写错的验收期望（脚本抓到的是我的问题）

第一次跑出 **35/36**，唯一失败是"审计里缺少 `admin_delete_content`"。原因不是实现漏写审计，而是**我的场景选错了**：我让管理员删掉**自己**发的主题，而该审计动作只在删除**他人**内容时写入（删除自己的内容走作者路径）。改成"成员发布 → 管理员删除"后即通过，这也正是 B5 要验证的那条路径。

值得记下：**验收脚本失败时，先确认场景是否真的触发了要验的路径**——这次差一点就把它当成审计缺陷记进报告。
