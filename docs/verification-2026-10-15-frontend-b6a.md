# B6a：我的内容与公开用户主页（2026-10-15）

## 结论

B6 的第一片（读者侧界面）已完成：`#/me/contents`「我的内容」与 `#/user/{public_id}`「公开用户主页（含其公开内容）」。管理端界面（B6b）与整体浏览器走查（B6c）仍未做。

## 做了什么

- `api/profiles.ts`：`listMyContents`、`getPublicUser`、`listUserContents`。
- `components/ContentCard.tsx`：把混排内容（帖子/回答/评论/删除占位）的渲染抽成共用组件。**搜索结果页原本有一份相同逻辑**，这次先落地共用组件，避免第三个页面再抄一遍。
- `views/MyContentsView.tsx`：`#/me/contents`，并导出 `ContentListView` 供公开主页复用。
- `views/UserProfileView.tsx`：`#/user/{public_id}`，资料 + 公开内容列表 + 自己的公开 ID 与注册时间。
- 路由：新增静态路由 `me/contents` 与参数路由 `user/{id}`；个人资料页加入口。

## 界面不做一侧的过滤

两个列表在界面上看起来一样，差别**全在服务端**：本人列表包含自己的匿名帖（仍以匿名模式渲染），公开列表在 SQL 里就排除了匿名行。界面因此**没有任何"显示/隐藏匿名"的开关可做，也不该有**——把它写在前端就等于给读取器留了一个泄露的机会。删除占位只显示服务端给的文案，界面不猜原文与作者。
