# OpenTalk 第一版需求

更新日期：2026-10-14。本文区分用户已确认的规则与实现建议；建议不等同于最终产品决定。

## 已确认范围

- React 前端、Go 后端、MySQL + Redis，自有服务器部署。
- 邮箱与密码登录；注册发送 SMTP 邮件验证码前必须完成图形验证码；支持找回密码。
- 昵称允许重复；内部用户 ID 与唯一的对外公开 ID 分离。
- 普通讨论板块与 Q&A 板块；发帖、提问、回答、评论及回复。
- 标签、Markdown、图片、基础搜索、站内通知及可选邮件通知。
- 举报帖子、问题、回答与评论；管理员后台。
- 第一版不包含收藏、点赞和答案采纳（已确认）。标签由管理员维护，用户发布时选择（已确认）。
- 游客可以浏览和搜索公开内容；发言和举报必须登录。

## 匿名

- 帖子、问题、回答和评论均可匿名，始终通过内部 user_id 关联真实作者。
- 一般情况下每条内容独立选择身份，同一讨论可混用匿名和昵称，发布前提示关联风险。例外（已确认）：匿名帖子或问题的作者，在该讨论下的自答、所有评论及回复必须匿名，包括其他回答下的评论及回复，统一显示“楼主”。
- 发布后不可切换该条内容的匿名状态。
- 同一讨论内，同一用户的匿名发言使用稳定编号；跨讨论不复用编号。
- 普通接口、页面源码、图片地址、搜索、个人主页、通知及邮件不得泄露匿名作者内部 ID、公开 ID、昵称或头像。
- 匿名楼主的评论和回复不提供取消匿名选项；服务端强制执行，不能仅依赖前端。作者本人仍有管理自己内容的权限。其他用户匿名发言继续使用讨论内匿名编号。
- 已确认：匿名提问者自答也继承匿名并显示楼主，避免自答绕过身份保护。实现建议：非匿名主题作者以昵称回复时显示楼主标识，以匿名回复时不显示关联标识。
- 匿名内容的个人主页公开列表不显示；作者可以在私有的“我的内容”中查看。
- 管理员追溯匿名身份需要专用权限与审计记录。

## 问答与评论

- 提问者手动设置“待解决/已解决”，可以重新打开问题。
- 解决状态与答案采纳独立；标记已解决不要求存在回答。
- 已确认：问题标记已解决后，整个问题下禁止新增回答、评论和回复，包括已有回答下的评论与回复，对提问者本人同样生效。已有内容保留。重新打开后恢复新增互动（仍需满足未删除、未锁定等条件）。这不自动禁止编辑或删除已有内容，后者按各自权限规则执行。
- 普通帖用评论交流；问题可添加澄清评论，回答也可添加评论。
- 建议采用两层评论展示；回复可以指向同一评论串中的具体评论。

## 删除与内容状态

- 已确认：删除帖子或回答时，同步软删除其下全部评论和评论回复；不再保留这些评论的公开原文。保留内部关联关系和删除占位，沿用30天审核保留规则。
- 已确认：删除问题时，同步软删除所有回答、问题下的评论，以及回答下的评论和所有关联回复。
- 按类型显示“该帖子/问题/回答/评论已被删除”；问题或帖子标题建议统一替换为“已删除的主题”。
- 删除原文仅供管理员审核，保留 30 天，之后清除原文。
- 删除立即影响公开接口、搜索、缓存、图片访问和待发送通知，不能等待清理任务后才隐藏。
- 已确认：单独删除评论时，递归软删除直接或间接回复该评论的关联评论；不删除其祖先或同串无关分支。父帖子、问题或回答被删除时，全部下属内容按上述范围一并软删除。已删除对象及下属内容禁止新增互动。
- 管理员隐藏用于违规处置，与作者删除分开；隐藏整个主题时，其回答和评论也不再公开。
- 原文清理应覆盖正文、标题及只被删除内容引用的附件；备份保留和到期清理需在上线前落实。
- 第一版暂不提供用户恢复删除内容的入口。

## 账号与验证码

- 邮箱规范化后唯一；公开 ID 唯一且不可变；密码只保存安全哈希。
- 图形验证码必须服务端验证、短期有效、单次使用，并绑定发送验证码的用途。
- 邮件验证码按邮箱与用途绑定，限制有效期、失败次数、重发间隔及邮箱/IP 发送频率。
- 验证成功后单次消费；注册并发请求不能创建重复账号。
- 登录连续失败需要限流；找回密码响应避免透露邮箱是否注册。
- 退出登录撤销会话；重置密码建议撤销已有会话。
- 正常、禁言、封禁分开；禁言阻止发言，封禁阻止登录并撤销会话。

### 账号阶段已确认参数（2026-10-14）

- 输入限制：密码 8–16 字符且必须同时包含字母和数字；昵称不超过 10 字符，每个字符必须是字母（汉字属于字母），不允许数字、空格、标点和符号；简介不超过 300 字符。长度按字符计数，并小于等于存储容量。
- 图形验证码：4 位字符，字符集去除易混淆的 0、O、1、I、L；有效期 5 分钟；单次使用；同一挑战最多提交 3 次。图片为 PNG 且禁止缓存，响应不包含答案。
- 邮件验证码：6 位数字；有效期 10 分钟；同一挑战最多校验 5 次；同一邮箱重发间隔 60 秒；每邮箱每小时最多 5 封；每 IP 每小时最多 20 封。
- 登录：同一邮箱连续失败 5 次后，后续登录请求必须同时提供图形验证码；计数按邮箱进行，不区分该邮箱是否已注册，避免泄露注册状态。
- 会话有效期 30 天，到期即失效。退出登录只撤销当前会话；重置密码撤销该用户全部会话。
- 邮箱规范化：去除首尾空白后做 Unicode 小写折叠。不合并 Gmail 点号或加号别名，避免把不同邮箱当成同一账号。
- SMTP 主机、端口、加密方式、账号、密码、发信人与显示名，以及上述验证码有效期限、最大校验次数、重发间隔、邮箱/IP 频率上限和登录失败阈值，全部由管理员后台修改；SMTP 密码在数据库中只保存密文，读取设置的响应不返回密码明文。
- 第一个管理员由运维命令创建或提升产生，不使用环境变量白名单，也不在迁移里内置种子账号。
- 邮件验证码保存在 Redis，不写入 outbox，也不进入业务通知表；不把明文验证码放进任何持久化业务表。

## 编辑、图片与链接

- Markdown 编辑与预览；服务端渲染或过滤必须与前端保持相同安全规则。
- 禁止危险 HTML、脚本协议及未经校验的链接；代码块按文本展示。
- 第一版仅上传常见图片；校验真实格式、大小、数量，移除元数据。
- 图片通过服务端受控路径提供，文件名和路径不包含作者身份。
- 站内链接直达；外链经过中间页，展示真实域名和继续访问入口。
- 本地草稿为实现建议，需按用户隔离，并在退出时避免下一个用户读取。

### 内容阶段已确认参数（2026-10-14）

- Markdown：接口只保存并返回 Markdown 原文。服务端用 goldmark 解析，写入时直接拒绝原始 HTML、`javascript:` 与 `data:` 等脚本协议、以及未经校验的链接；前端用 markdown-it 渲染并关闭 HTML 直通，使用与后端同一份链接白名单。两端共用一张「允许/禁止」清单，清单变更必须同时改两端，不允许只改一侧。
- 图片：文件存放于 `data/media/<随机storage_key>`；只接受 PNG、JPEG、WebP、GIF；单张不超过 5 MiB、像素不超过 4096×4096；每篇内容最多 9 张；上传时移除元数据。文件路径与文件名不含作者身份。
- 图片清理：未关联任何内容的待用附件保留 24 小时后清除；内容被删除后，其附件若不再被任何有效内容或未到期的审核归档引用，7 天后物理清除。清理失败可重试，不把失败提前标记为完成。
- 图片限制（单张字节上限、像素上限、每篇张数）与上述两段清理时长，与账号阶段的验证码、限流参数放在同一处由管理员后台修改。
- 初始板块由 `cmd/admin -action seed-boards` 预置「综合讨论」（讨论板块）与「问答」（Q&A 板块）；迁移只建结构，不写业务数据。
- 匿名展示：同一讨论内使用稳定编号，界面与邮件显示为 `匿名#3`；匿名楼主统一显示 `楼主`，不再显示编号。跨讨论不复用编号（沿用已有规则）。
- 编辑时限：自己的内容在发布后 30 分钟内可编辑，超过时限只能删除重发。锁定主题仍禁止编辑正文（沿用已有规则）；已解决问题不额外禁止编辑。管理员不因时限获得代改权限，仍通过审核操作处理。
- 长度与数量限制：标题为单行纯文本，1–120 字符，不接受换行与控制字符；正文为 Markdown 原文，1–20000 字符；每篇内容最多选择 5 个标签。均按字符计数，且小于等于存储容量（标题列240、正文MEDIUMTEXT）。

## 通知

- 站内通知覆盖新评论、新回答、收到回复和管理处理结果。
- 用户设置全局邮件偏好；每个主题可覆盖是否接收邮件。具体事件以用户勾选为准。
- 自己的操作不通知自己；同一事件对同一接收者去重。
- 邮件后台发送，失败可重试；SMTP 故障不回滚发帖或回答。
- 发送前重新检查内容可见性、身份展示和订阅设置。
- 邮件提供取消订阅入口；用户关闭邮件不影响站内通知。
- SMTP 服务商与发信域名，以及通知邮件自身的发送频率与合并窗口，在实现通知邮件前确认；验证码邮件的频率上限已在账号阶段定稿。

## 管理

- 第一版使用普通用户、管理员两类角色。
- 举报需要原因，可补充说明；同一人对同一对象只允许一个未处理举报。
- 举报人身份不公开；举报数量不直接触发自动删除。
- 管理员处理举报、隐藏/锁定/移动主题、管理标签和板块、禁言或封禁用户。
- 处理结果通知相关用户；管理操作和匿名身份追溯写入审计日志，日志不复制被删正文。

## 核心验收场景

1. 未通过图形验证码无法发送注册验证码；过期、重放和超限请求均被拒绝。
2. 昵称重复可以注册，邮箱或公开 ID 重复不可以。
3. 匿名发言可由作者管理、管理员追溯，游客与其他用户无法从接口或邮件得到作者标识。
4. 匿名主题作者的所有评论与回复强制匿名并显示“楼主”，伪造非匿名参数不能绕过；其他参与者仍可逐条选择身份，匿名编号稳定。
5. 只有提问者能主动切换解决状态；无回答也可标记已解决并重新打开。已解决时任何人新增回答、评论和回复必须被服务端拒绝，包括与状态切换并发的提交；重新打开后按权限恢复。
6. 删除帖子或回答后，其下全部评论和回复同步软删除；删除问题同时删除其全部回答及评论；单独删除评论递归删除关联回复，不影响无关分支。所有相关原文不可公开读取；30 天后审核原文和符合条件的附件被清理。
7. 关闭邮件后不再发送相关邮件；SMTP 不可用时内容仍发布成功。
8. 被隐藏主题无法经回答、评论、附件和搜索接口绕过可见性检查。
9. 禁言用户不能新增或编辑发言；越权编辑、删除与切换解决状态被拒绝。
10. 未登录、普通用户和禁言用户都不能读取或修改站点设置；修改SMTP与限流参数后新值立即生效，读取设置、错误信息和审计记录都不包含SMTP密码明文。
11. 退出登录后原会话立即失效；重置密码后该用户全部既有会话失效；封禁用户不能登录且既有会话被撤销。
